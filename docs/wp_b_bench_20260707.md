## Decoder Capacity Fix

The first 30 x 1280-byte run delivered no RF data. Root cause: the firmware
KISS decoder still capped decoded KISS payloads at `TNC_PAYLOAD_MAX_LEN`
1280 bytes, but generic-mode USB input carries an 8-byte serial-integrity
header, so a max payload arrives as a 1288-byte KISS payload.

Fix applied during Phase 8:

- `KissFrame` and the internal KISS decode buffer now use
  `KISS_FRAME_PAYLOAD_MAX_LEN = TNC_PAYLOAD_MAX_LEN + SERIAL_INTEGRITY_HDR_LEN`.
- The legacy `Kiss::decode(PayloadFrame&)` helper rejects decoded frames above
  `TNC_PAYLOAD_MAX_LEN` before copying into `PayloadFrame`.
- Native KISS tests now include max-size wrapped generic frame coverage.

## Fixes Applied During Gate

- Raised firmware KISS decode capacity for generic-mode USB frames to
  `TNC_PAYLOAD_MAX_LEN + SERIAL_INTEGRITY_HDR_LEN` while keeping
  `PayloadFrame` capped at 1280 bytes.
- Added a v3 DATA round-end flag and deferred partial ARQ ACKs until the end of
  a transmit round. This avoids fragment-by-fragment ACK/DATA contention on the
  half-duplex radio path.
- Used the existing `RADIO_INTER_FRAG_DELAY_MS` pacing for v3 DATA sends so the
  peer has time to re-arm RX between packets.
- Raised `TX_QUEUE_DEPTH` from 8 to 32 so firmware can absorb the Phase 8
  zero-gap 30-frame USB ingress burst while the radio drains at paced speed.
- Chunked USB CDC serial TX writes to 64-byte pieces with a one-tick yield
  between chunks, which removed the observed one-frame host serial-integrity
  truncation in the reverse-direction run.

## Egress Blockage And Bidirectional Pressure

I exercised the host-side blockage path with a no-read receiver on
`/dev/ttyACM0` and a larger zero-gap burst from `/dev/ttyACM1`:

- `raw_fragment_test.py send --sizes 1280 --count 80 --interval-ms 0`.
- Sender completed 80 writes and reported `arqV3TxDone=79` at shutdown.
- Reopening `/dev/ttyACM0` after the blocked period did not recover any queued
  payloads; the reopen returned `frames=0`.

I also ran concurrent transmit pressure by starting the same 80-frame zero-gap
burst on both `/dev/ttyACM0` and `/dev/ttyACM1` at the same time. Both helpers
completed the transmit loop, but the final `STATS` queries timed out, so that
run is not yet a clean closeout artifact.
